01 · 问题

AI 写代码很快，
难的是让它一直靠谱。

猜

它看不全，就开始猜

仓库一大，模型读不完，只好凭印象改。改动越多，代码和文档越对不上，下一次猜得更离谱。

漏

没人把关，错误直接上线

AI 一天能交几十个改动，人工逐行审查跟不上；靠"记得要检查"的规矩，迟早会漏。

乱

交付没有节奏

改动随时合、随时发，出了问题说不清是哪一个改动、为什么这么做、当时谁拍的板。

方案

把研发流程写成机器能执行的规则。

像一条生产线：每个改动都过同样的七道工序。人只做判断，流程和质检交给机器。

  1. 需求先认领，再动手
  2. 追问规则写回仓库
  3. 规格三件套
  4. 实现子 Agent 闭环
  5. 守卫推送前全绿
  6. 集成自开 PR 自盯
  7. 上线每日列车

02 · 自动化代码开发工厂 · claude-dev-harness

需求进去，上线的代码出来。

先打个比方

AllyNutra 本身就是一家工厂。

原料进去，按配方、按工序、过质检，胶囊出来。我给它的软件也建了一座工厂：需求进去，按规格、按工序、过质检，上线的代码出来。模型是厂里最快的那台机器，下面七层厂房让它不出次品。

第 1 层 · 图纸库

只给地图：1 张根地图 + 25 张模块地图

模型从不通读整个仓库。先查路由表，只读一个目的地，再打开源码。地图本身有篇幅预算守卫，不许越写越长。

  • 工具短文 · 2026-11-28

    AI 写的 Python 脚本一到中文 Windows 就乱码,怎么根治?

    根因是 Python 在没写 encoding 时按系统代码页(中文 Windows 是 gbk)解码子进程输出、编码自己的 print。光在项目说明里叮嘱 AI 不够;我在 AllyOS 里加了两道 AST 静态检查:文本模式的 subprocess 调用必须写 encoding="utf-8",每个脚本的 main() 第一行必须把标准输出钉成 UTF-8。612 个文件扫一遍约 1.5 秒,过去 30 天拦下 7 次 AI 漏写。

  • 事故复盘 · 2026-11-27

    Claude Code 子 Agent 一开 worktree,Git 钩子为什么就跑错了?

    Claude Code 每次新建 worktree(包括子 Agent 的工作树隔离),都会把共享 .git/config 里相对写法的 core.hooksPath 改成主目录的绝对路径,之后没单独钉住配置的工作目录都会去跑主目录那份 Git 钩子。解法是把同一个"改回相对路径"的修复脚本同时挂到 SessionStart、PostToolUse(EnterWorktree)和 SubagentStart 三个入口,实测 68 毫秒内复原。
