# Repo Map 模板：先定位，再读取

> 通用化公开模板，不是任何客户仓库的内部文件。用于多 Agent 协作时提供稳定指针，避免把整库实现复制进上下文。把尖括号内容替换为自己的仓库信息；没有的内容写“未知”，不要让 Agent 猜。

## 使用约定

1. Agent 先读根地图，再按任务打开一个模块子地图，最后才读相关源码。
2. 地图只记录稳定事实：入口、职责、所有权、边界、命令和禁止事项；不复制实现细节。
3. 所有指针使用仓库内相对链接。目标不存在或命令不可执行时，必须报错，不能静默跳过。
4. 每个结论只保留一个事实来源。规格、代码、测试和发布记录通过任务编号互相关联。
5. 模块边界或命令变化时，在同一个改动中更新地图。

## 6. 自动守卫

| 守卫 | 拦截什么问题 | 执行入口 | 失败输出必须包含 |
|---|---|---|---|
| `<名称>` | `<可判定的问题>` | `<命令或钩子>` | `<规则、证据、修复方式>` |

每道守卫必须满足：

- 缺工具、缺配置、缺前提时失败关闭，不以“跳过”冒充通过。
- 同一输入重复运行得到同一结论；通过或失败都有明确退出码。
- 至少有一个“应当拦截”的自测样例，防止守卫永远报绿。
- 修复代码、测试、迁移或配置时，同步检查对应文档指针是否仍然有效。


## 10. 合并前核对

- [ ] 根地图和子地图中的相对链接都存在。
- [ ] 命令已在干净环境验证，失败不会被脚本吞掉。
- [ ] 模块职责、依赖方向、数据写入口仍然准确。
- [ ] 新规则已变成可执行检查，而不只是一句提醒。
- [ ] 没有把真实业务数据、凭据、内部域名或私有路径写进地图。
